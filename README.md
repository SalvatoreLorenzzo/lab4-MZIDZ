# IMDb ETL на PySpark

Лабораторна робота №4 з дисципліни «Методи та засоби інженерії даних та знань».

## Запуск

Потрібні Python 3.12 і Java 17. На Windows рекомендовано WSL Ubuntu: для прямого запису Hadoop у Windows також потрібні відповідні нативні бібліотеки.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py --data-dir imdb-data --output results --cache cache
```

Покладіть у `imdb-data` сім оригінальних архівів: name.basics, title.akas, title.basics, title.crew, title.episode, title.principals, title.ratings із розширенням `.tsv.gz`. Дані: https://datasets.imdbws.com/ . Опис полів: https://data.imdb.com/non-commercial-datasets/ . Архіви та результати не відстежуються Git.

Перший запуск читає всі рядки архівів із явними схемами, перевіряє формат і створює проміжні Parquet-таблиці. Для незмінених архівів наступний запуск повторно використовує цей шар. Відбиток джерела включає розмір і час зміни файлу; після заміни архіву зі збереженням обох атрибутів видаліть відповідний підкаталог cache перед повторним запуском.

`results/task1` ... `results/task8` містять повні результати TSV, `summary.json` – кількості рядків, `preview.json` – невеликі приклади. Spark створює каталог із файлами `part-*.csv`; у файлах використано табуляцію. Для швидкого перегляду збережених результатів у консолі:

```bash
python main.py --output results --view 1,2
python main.py --output results --view 3,4
python main.py --output results --view 5,6
python main.py --output results --view 7,8
```

`--view` читає збережені приклади реального виконання, без повторного розрахунку. `--tasks 7,8` перераховує лише вибрані завдання. Усі запити містяться в `queries.py`.

## Правила перетворення

1. Вибір назв для region=UA. Мову також збережено: регіон і мова є різними полями.
2. Народження від 1801 до 1900 включно.
3. Лише titleType=movie, тривалість строго понад 120 хвилин; оригінальні назви з title.akas.
4. Actor/actress, ім’я, оригінальна назва й персонажі у JSON-записі IMDb; невказані персонажі лишаються NULL.
5. Унікальні adult-твори в кожному відомому регіоні; повтори локалізованих назв не множать кількість. Топ-100.
6. Кількість різних ідентифікаторів епізодів у кожного tvSeries/tvMiniSeries; топ-50. Номери епізодів не підсумовуються та не замінюють кількість записів.
7. Як у прикладі методички, не-adult фільми; рейтинг за спаданням, кількість голосів за спаданням, tconst для остаточного розв’язання нічиєї. Десятиліття починаються з року, кратного 10.
8. Ті самі критерії рейтингу; до 10 назв у кожному окремому жанрі. Багатожанрові фільми потрапляють до кількох груп.

Мінімум голосів не встановлено, відповідно до прикладу методички. Тому це ранжування за averageRating, а не достовірна оцінка масової популярності: фільм із малою кількістю голосів може отримати високий ранг. Групи з менш ніж десятьма відповідними фільмами містять усі доступні записи.

## Перевірка

```bash
python test_etl.py
```

Тест запускає ті самі Spark SQL-запити на малому наборі: перевіряє межі років і тривалості, повторні назви, різні мови для UA, два сезони з номером епізоду 1, кілька жанрів та стабільне ранжування. Повні результати IMDb додатково перевіряються під час виконання.

Репозиторій: https://github.com/SalvatoreLorenzzo/lab4-MZIDZ . Використано гілки main, develop і feature з Pull Requests.

Документація: https://spark.apache.org/docs/3.5.8/sql-data-sources-csv.html , https://spark.apache.org/docs/3.5.8/sql-ref-syntax-qry-select-window.html .
